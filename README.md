# EduPlatform — упрощённая версия

Четыре Django-приложения, обычные HTML-формы, PostgreSQL, WebSocket через Channels
и Redis, Telegram через aiogram. Сохранены группы, материалы, задания, оценки,
посещаемость, чат, руки, опросы и уведомления.

В архиве нет тестовых файлов, тестовых настроек, демонстрационных данных,
GitHub Actions, скриптов настройки, виртуального окружения и секретов.

## Что изменилось

- Один requirements.txt с восемью основными зависимостями, без большого lock-файла.
- Сервер Uvicorn вместо Daphne. Больше не нужны Twisted, Autobahn и их зависимости.
- WhiteNoise удалён. При DEBUG=1 локальную статику обслуживает Django.
- Сложные выражения разложены на отдельные действия, словари и циклы.
- В views, services и consumers добавлены комментарии о назначении функций.
- Обычные проверки роли, группы, дедлайна и оценки сохранены.
- Модели и начальные миграции совместимы с предыдущим архивом.

Двухфакторной/трёхфакторной авторизации нет. Для входа нужны логин и пароль.
Ссылка привязки Telegram нужна только для подключения бота, при обычном входе
код из Telegram не запрашивается.

## Зависимости

| Пакет | Назначение |
|---|---|
| Django | Модели, формы, страницы, авторизация |
| channels | WebSocket-обработчики |
| channels-redis | Передача событий через Redis |
| psycopg[binary] | Подключение к PostgreSQL |
| aiogram | Telegram-бот |
| python-dotenv | Чтение .env |
| uvicorn | Сервер HTTP и WebSocket |
| websockets | Поддержка WebSocket для Uvicorn |

Это восемь основных зависимостей, а не восемь пакетов во всём окружении.
pip автоматически установит служебные зависимости этих библиотек. В частности,
asgiref нужен Django/Channels, msgpack — channels-redis, а aiohttp, pydantic,
magic-filter и их зависимости — aiogram. Их нельзя просто исключить и сохранить
те же библиотеки. Вручную импортировать все эти пакеты в своём коде не нужно.

Основные версии закреплены через ==. Версии косвенных зависимостей выбирает pip
по требованиям библиотек; эта версия не фиксирует полное окружение lock-файлом.

## Запуск через Docker Desktop

Откройте папку с manage.py и compose.yaml в терминале. Запустите Docker Desktop
и дождитесь готовности Linux Engine. Python на компьютере для этого способа не нужен.

Если уже есть рабочий .env, используйте его. Для новой установки:

```powershell
Copy-Item .env.example .env
notepad .env
```

Замените значения-заглушки SECRET_KEY и POSTGRES_PASSWORD случайными строками.
Чтобы получить строку, выполните в PowerShell (по одному результату для каждого поля):

```powershell
[guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
```

Для локальной работы оставьте DEBUG=1 и остальные значения из .env.example.
Затем запустите:

```powershell
docker compose up --build -d
docker compose ps
```

Откройте http://localhost:8000/. Зарегистрируйте преподавателя и ученика через сайт.
Готовых аккаунтов в архиве нет. Преподаватель создаёт группу, ученик вступает по коду.

Миграции применяет контейнер init. Его завершение с кодом 0 нормально.
Для администратора:

```powershell
docker compose exec web python manage.py createsuperuser
```

Панель администратора: http://localhost:8000/admin/.

## Telegram

Создайте бота через @BotFather. Заполните в .env:

```dotenv
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_BOT_USERNAME=имя_бота_без_символа_@
```

Запустите процессы с новыми настройками:

```powershell
docker compose --profile telegram up --build -d --force-recreate web worker bot
```

На сайте: Профиль → Подключить Telegram → Открыть бота → Запустить.
Сайт работает и без бота. runbot получает команды, runworker отправляет уведомления
и создаёт напоминания. Для одного токена нужен один процесс runbot.

## Запуск без контейнера web

Нужен Python 3.12. Создайте .env как выше. PostgreSQL и Redis оставьте в Docker:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
docker compose up -d db redis
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe -m uvicorn config.asgi:application --host 127.0.0.1 --port 8000 --reload
```

В другом терминале:

```powershell
.\.venv\Scripts\python.exe manage.py runworker
```

Для Telegram также запустите .venv\Scripts\python.exe manage.py runbot.
На Linux/macOS путь к интерпретатору: .venv/bin/python.

В этой версии используйте Uvicorn, а не manage.py runserver: стандартный runserver
без Daphne не обслуживает WebSocket. Не запускайте web в Docker и локальный сервер
на одном порту одновременно.

## Обновление предыдущей установки

Сохраните свой .env, загруженные файлы и прежнее имя Compose-проекта. База остаётся
совместимой: таблицы, поля и миграции не менялись. Код учебных функций стал понятнее.

Распакуйте новые исходники в прежнюю папку проекта и верните .env. Если копируете
поверх старых файлов, уберите старый requirements.lock.txt и оставшиеся тестовые/
демофайлы вручную: копирование не удаляет отсутствующие в новом архиве файлы.

После замены:

```powershell
docker compose up --build -d
```

Если используете Telegram, добавьте --profile telegram перед up.
Не переименовывайте папку Compose-проекта без необходимости: имя папки по умолчанию
влияет на имена volumes. Новый проект может подключить новую пустую базу вместо старой.
Замена .env не меняет пароль существующего пользователя PostgreSQL автоматически.
Удаление кода демоданных не удаляет записи, ранее созданные в вашей базе.

## Полезные команды

```powershell
docker compose logs --tail=80 web init worker bot
docker compose exec web python manage.py check
docker compose --profile telegram down
```

Обычный down сохраняет данные. Параметр -v удаляет хранилища с базой и файлами.

## Как читать код

Начните с docs/ARCHITECTURE.md. Затем разберите один путь:
config/urls.py → education/views.py → education/forms.py → education/models.py.
После обычных страниц переходите к education/services.py и education/consumers.py.

## Границы этой версии

Локальная учебная сборка: DEBUG=1, HTTP, порты доступны только на этом компьютере.
При DEBUG=0 статические файлы должен обслуживать отдельный веб-сервер, например Nginx,
из папки collectstatic. Для публичного размещения также нужны HTTPS, настройки домена,
secure cookies, ограничение частоты запросов и резервное копирование.

Файлы пользователей всегда выдаются через views с проверкой доступа; private_media
не следует публиковать как статическую папку. Пароли хранит стандартная система Django.

Посещаемость подтверждает соединение со страницей, а не присутствие в Zoom.
Heartbeat идёт раз в 30 секунд, таймаут — 90 секунд. Несколько вкладок не удваивают время.
Один преподаватель у группы, один активный опрос, одна обновляемая сдача на задание.
Очередь Telegram повторяет временно неудавшиеся отправки. При аварии между отправкой
и записью её результата возможен дубль. Пропущенные окна напоминаний не рассылаются задним числом.

## Что проверено перед передачей

Проверка Django, соответствие миграций моделям, отсутствие конфликтов зависимостей;
сценарии ролей, заданий, посещаемости, опросов и привязки Telegram проверены отдельно
от передаваемой папки. В браузере на Uvicorn проверены вход, страницы и статика,
начало занятия, чат, рука, опрос, сдача работы и выставление оценки.

Проверки выполнены на отдельной SQLite-базе и InMemoryChannelLayer. Доступ к Docker
Engine в среде сборки отсутствовал, поэтому полный Compose-запуск с PostgreSQL/Redis
не подтверждён. Реальная доставка в Telegram требует вашего токена и не проверялась.
Тестовые файлы, настройки проверок, данные и скриншоты в этот архив не включены.
